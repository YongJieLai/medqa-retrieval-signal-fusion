# 云服务器部署清单（P0 失效基线实验）

> 目标：在 RTX 4090（24GB）云服务器上完成「MedCPT 语义检索 + PubMed 语料」的 8 配置失效基线实验，绕开本地 8GB 内存 + CPU 编码的 OOM 瓶颈。

---

## 一、服务器规格

| 项 | 要求 |
|---|---|
| GPU | 1× RTX 4090（24GB）即可，A10/3090 亦可 |
| 内存 | ≥32GB（推荐 64GB，编码 173 万篇时余量充足） |
| 存储 | ≥50GB 系统盘（数据约 7GB） |
| 系统 | Ubuntu 20.04/22.04 + CUDA 12.1 + Python 3.10 |
| 平台 | AutoDL（推荐，RTX 4090 约 1.5-2 元/小时，按小时计费） |

> **显存只需 24GB**：MedCPT 是 BERT-base（110M），batch=256 编码仅用 3-4GB 显存。不需要 A100/H100。

---

## 三、云服务器执行步骤

```bash
# 1. 解压
mkdir -p ~/repo && tar xzf p0_cloud_pkg.tar.gz -C ~/repo && cd ~/repo

# 2. 确认 .env 里的 key 已更新（这是推理的前置条件）
cat .env

# 3. 一键执行（装依赖 → 编码 → 跑推理）
bash scripts/setup_cloud.sh
```

预期：
- **编码**：GPU 上 173 万篇约 10-20 分钟
- **推理**：8 配置 × 200 题 = 1600 次 API 调用，约 30-60 分钟（取决于 API 速率）

## 四、产出与回传

| 产出 | 路径 |
|---|---|
| FAISS 索引 | `kg/medrag_pubmed/index.faiss`（~5.5GB） |
| 语料元数据 | `kg/medrag_pubmed/corpus_meta.jsonl` |
| 实验结果 | `results/results_p0.jsonl`（8 配置 × 200 题） |

回传时只需下载 `results/results_p0.jsonl`（很小），索引和语料可留在服务器或删掉。

## 五、前置条件（阻塞项）

1. **API key**：`.env` 里的 `DASHSCOPE_API_KEY` 必须是**有效**的（当前 key 已 403）。推理环节完全依赖它。
2. 若 key 仍未恢复，可在服务器上先跑完「编码建索引」（步骤 1-4，不依赖 key），推理等 key 就绪后再跑步骤 5。

---

## 六、备选（若 API key 长期不可用）

用本地部署 qwen3:8b 替代 DashScope API：
- 在服务器上 `ollama pull qwen3:8b`（服务器网络不受本地限制，可直连）
- 修改 `run_p0_baselines.py` 的 `call_llm` 走 Ollama 本地接口（`http://localhost:11434`）
- 这样彻底绕开 API key，但 8B 模型在 4090 上推理速度尚可
