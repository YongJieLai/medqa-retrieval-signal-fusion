# 代码纪律

> 本文是实现方（写代码的 agent / 开发者）必须遵守的规范。核心原则与《技术交接文档》一致：**照着做即可，不要改动口径，拿不准先问，不要自己发挥。**

---

## 1. 总纲：口径锁定

1. **定义、公式、实验口径一律照文档实现**，不得自行"优化""简化"或换一种等价的写法，除非等价性已被明确确认。
2. 拿不准的地方**先问，再动手**；不要凭直觉补齐文档未写明的细节，更不要把"我猜的默认值"写死进代码而不标注。
3. 任何偏离文档的实现，必须：① 在代码中用注释标注 `DEVIATION:`；② 在 PR 描述中说明理由；③ 等待确认后合入。

## 2. 模块边界（不得越界）

严格按四层拆分，层与层之间只通过明确的数据接口通信：

| 模块 | 职责 | 禁止 |
| --- | --- | --- |
| `signal`（信号层） | 概念清单 → 分层 → 定价 → `coverage(q)` | 不读模型内部；不接触答案字段 |
| `allocation`（分配层） | 子模贪心 / MVP 排序取 top | 不自己重算信号；不做逐题二元触发 |
| `execution`（执行层） | 检索执行 → 给模型 → 答题 | 不篡改分配决策 |
| `eval`（评测层） | 四象限切分、秩相关、正确率、消融 | 不污染信号计算 |

- **守住定位**：做"跨题全局分配 + 连续分数"，**不做**"逐题二元检索触发"，**不做**"答题中防幻觉"（那是 QuCo-RAG / Marina 的位置，不要滑过去）。
- 第一步的模型侧门控是"二元、在分配之前的门控"，**不混进价值函数**。

## 3. 信号实现红线（本文贡献的核心）

1. **模型无关**：信号只查知识图谱与语料，**严禁**读取 logits、隐层、自评、token 概率等任何模型内部状态。
2. **答题前约束**：所有信号必须仅用 `{题干, 四个选项}` 计算，**答案字段不得出现在信号计算的任何代码路径或数据流中**（防止泄漏）。
3. **模型冻结**：不改模型、不训练、不微调；信号本身也不得引入可训练参数。
4. **必要性按公式代入**：`ν_c = P(E_I) · α(c)`，是缺失概率向量 p⃗ 的解析函数；路径只是输入，**严禁"数经过 c 的路径条数"当必要性**。
5. **概念召回宁多勿漏**：噪声交给"稀有度 × 必要性"权重自然压制，不要为了"干净"在召回阶段就砍概念。
6. **coverage 是估值信号，不是答对概率**：变量命名、注释、日志都要体现这一点，不要命名为 `prob_correct`、`accuracy` 之类误导性名字。

## 4. 公式实现规范

1. 公式必须以 §4「关键公式速查」为准，逐字符对齐；数值计算用高精度浮点，注意 `σ(x)=1/(1+e^{−x})` 的数值稳定实现（如 `x<0` 时用等价变换避免上溢）。
2. 每个公式函数必须配**单元测试**，用解析手算的小样例（如 1~3 个概念、1~2 条路径）校验到小数位。
3. 关键常量集中管理、注释来源：
   - `τ = 1.0`（初始，网格 `{0.5, 1.0, 2.0}`）
   - `idf_median` = 当前数据集所有概念 IDF 的中位数
   - PMI 最低共现次数 `N(q,c) ≥ 2`
   - 实体映射 embedding 相似度阈值 `0.85`

## 5. 可复现性

1. 全局随机种子固定（数据切分、检索、模型采样），种子值统一由配置注入并写进实验日志。
2. 依赖版本锁定（`requirements.txt` / `pyproject.toml` / conda env 导出），模型与 KG 的版本/下载源记录在 `docs/` 或 `configs/`。
3. 任何"随机"行为（贪心 tie-break、路径枚举顺序、模型温度）都要确定性或可 seed。

## 6. 命名与代码风格

1. 变量/函数名**忠实于公式符号**：`p_c`（缺失概率）、`nu_c`（必要性）、`mg_c`（边际增益）、`coverage`（题目分数）、`S(P)`、`S_neg_c`、`P_EI`、`alpha_c`。
2. 核心数学对象（概念、路径、题目）用显式类型或 dataclass 表达，字段名与公式对应。
3. 中文注释允许且鼓励，用于解释"为什么"，代码本身自解释"是什么"。

## 7. 数据接口与管道

1. 题目输入统一 schema：`{question_id, stem, options[4], answer}`；其中 `answer` 仅执行层/评测层可读，信号层与分配层的数据对象中**不得带 answer**。
2. 决策输出统一 schema：`{question_id, action ∈ {closed, retrieve}}`。
3. KG、语料、数据集的加载与预处理脚本独立，产出可缓存中间产物（如概念索引、IDF 表、最短路径缓存），避免每次实验重复计算。
4. 中间产物与缓存**不入库**（加入 `.gitignore`），只入库脚本与配置。

## 8. 测试与 CI

1. 公式函数、分配函数（MVP 排序 + 子模贪心）必须有单元测试。
2. 实验脚本至少有一个 smoke test（小样本、小预算能端到端跑通）。
3. 提交前本地跑通测试；禁止提交破坏 CI 的代码。

## 9. Git 纪律

1. **严禁提交任何密钥、token、私有数据、模型权重、大数据文件**。token 只用于本地认证，不得出现在任何被跟踪文件里。
2. 提交信息语义化（`feat:` / `fix:` / `exp:` / `docs:` / `refactor:`），一次提交一件事。
3. 实验相关的数据/结果变更与代码变更分开提交，结果表（`.csv`）走单独目录（如 `results/`）。

## 10. 交付物自检清单

- [ ] 信号层：概念清单（双锚点 + 四层召回 + 三阶段实体映射）→ 概念分层 → 稀有度/必要性 → `coverage(q)`
- [ ] 分配层：先跑通"按 coverage 降序取前 B 道"的 MVP，再做完整子模贪心
- [ ] 实验脚本：四象限切分 + 四个实验的评测（秩相关 / 三臂 / 消融 / 跨模型）
- [ ] 结果：四象限分象限结果，输出成 `.csv` / 表格
